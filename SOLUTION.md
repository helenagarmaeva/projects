# ArbiHunter — главный экран работодателя

## Задание и границы

Исходный бриф: HR-сервис ArbiHunter. Главная работодателя после входа почти не используется: баннер, профиль компании, вакансии, подписка, статистика и медиа не помогают быстро продолжить найм. Нужно переосмыслить главный экран так, чтобы работодатель понимал состояние вакансий, число новых кандидатов, требующие внимания действия, проблемы и следующий шаг.

Нужно подготовить: (1) краткий анализ исходного экрана; (2) роль нового главного экрана; (3) новый дизайн; (4) UX-сценарий на 2–4 экрана или состояния; (5) visual style guide с цветами, типографикой, карточками, кнопками и статусами; (6) небольшой UI-kit. Формат исходного задания — ссылка на Figma, Desktop и Mobile, срок один день. Оценка — не только визуальное исполнение, но и постановка задачи, приоритеты, сценарии, аргументация.

По прямому указанию пользователя реализован **только один экран с адаптивом и состояниями**, без дополнительных страниц. Визуальный источник — тёмный экран ArbiHunter (второе показанное изображение; порядок картинок в сообщении отличается от словесного описания). Новые анимации не вводились, добавлены hover-состояния. Эта сдача — HTML/CSS/JS и документация в новой Git-ветке, **не Figma-файл**. Доступных инструментов записи в Figma нет.

## 1. Анализ текущего экрана

| Наблюдение по скриншоту | Почему мешает |
|---|---|
| Крупный рекламный баннер сразу после поиска | Первый экран отдаёт внимание сторонней активности, а не продолжению найма. |
| Заголовок и поиск ориентированы на поиск сотрудников | После входа не видно состояния уже запущенной работы. |
| Вакансии в узкой колонке рядом с профилем и промо | Названия ломаются, нет места для откликов, сроков и связанных действий. |
| Все показанные вакансии — черновики с одинаковым действием | Не раскрыт рабочий сценарий работодателя с опубликованными вакансиями. |
| Статистика платформы в блоке медиа | Общие числа сервиса не отвечают на вопрос «что происходит у меня». |
| Подписка визуально конкурирует с вакансией | Продажа тарифа опережает решение текущей задачи. |
| Отзывы и большой подвал занимают значительную часть страницы | Увеличивают длину служебного экрана без пользы для ежедневного найма. |
| Нет явной очереди внимания | Пользователь самостоятельно ищет, где появились кандидаты и что требует решения. |

Это экспертные гипотезы по изображению, а не результаты интервью или аналитики.

## 2. Роль нового экрана

Рабочая точка входа в найм: за короткий просмотр понять объём работы, выбрать приоритет и выполнить ближайшее действие. Иерархия: **личная сводка → действия → вакансии → вспомогательная информация**. Создание вакансии остаётся доступным, но не вытесняет работу с существующими откликами.

| Вопрос из задания | Ответ в интерфейсе |
|---|---|
| Что происходит с вакансиями? | 6 активных, 3 черновика; список с количеством откликов и статусами. |
| Сколько новых кандидатов? | 12 новых по 3 вакансиям, +5 сегодня; у строк +7/+3/+2. |
| Какие действия требуют внимания? | Отдельная очередь из 3 задач с контекстными кнопками. |
| Где проблемы? | 0 откликов за 7 дней у ASO, истечение публикации PMM завтра. |
| Что сделать сейчас? | Первое действие — рассмотреть кандидатов, далее проверить вакансию и продлить публикацию. |

Числа, имена, время, статусы, срок продления30дней и причина проблемы ASO — **демонстрационные допущения**, а не данные исходного продукта. Отображены только три имени кандидатов как пример обработки; 12 — агрегат по всем вакансиям. В продуктовой реализации суммы, события и сроки приходят из API.

## 3. Дизайн и адаптация

Desktop: сохранены левое меню, верхняя служебная панель, тёмные поверхности, фиолетовый основной акцент и небольшая оранжевая метка Plus. Контент расширен относительно узкой колонки исходника: четыре показателя, затем две зоны — работа и поддерживающая информация. Личный профиль, активность и тариф не конкурируют с задачами. Баннер и отзывы не входят в ежедневную рабочую сводку.

Mobile≤760px: меню открывается кнопкой; показатели в две колонки; очередь задач, вакансии и боковые блоки идут последовательно. Таблица становится вертикальными строками с прежними данными, статусы подписаны. Фильтры допускают горизонтальную прокрутку. Действия остаются рядом со своей задачей. На планшете боковая колонка переносится вниз.

Не добавлены страницы профиля, поиска, вакансии, чата, оплаты или создания вакансии. Их кнопки явно сообщают о границе прототипа, а не имитируют переход. Нет заставок, входных анимаций или подъёма карточек. Hover меняет только тон/рамку/цвет.

## 4. UX-сценарий: 3 состояния одного экрана

**Цель:** начать обработку новых кандидатов после входа.

1. **Обзор.** Работодатель видит 12 новых кандидатов и задачу первого ответа. Нажимает «Рассмотреть».
2. **Фокус на откликах.** Выбран фильтр «С новыми откликами», показаны 3 релевантные вакансии. Внутри той же секции раскрывается список кандидатов Affiliate-менеджера. Можно свернуть список, выбрать другую вакансию или сменить фильтр.
3. **Результат действия.** «Пригласить» у выбранного кандидата меняется на «Приглашён», повторная отправка блокируется, доступно подтверждение для скринридера. Остальные кандидаты остаются на месте.

Дополнительные состояния в рамках той же страницы: «Черновики», «Показать ещё3вакансии», рекомендация для ASO, публикация продлена. После продления PMM становится опубликованной, задача исчезает, счётчик внимания уменьшается3→2. Состояния живут в памяти страницы, после перезагрузки сбрасываются. Отправки приглашений на сервер и списания денег нет.

## 6. UI-kit

| Компонент | Варианты и состояния |
|---|---|
| Primary Button | Фиолетовая заливка, светлый текст,42px; compact36px; hover светлее; видимый focus. |
| Secondary Button | Тёмно-серая заливка, светлый текст; hover тон+рамка; compact и full-width. |
| Icon Button | Прозрачный фон,38×38px; нейтральный hover; доступное имя. |
| Nav Item | Default muted, hover neutral, current purple soft. |
| Metric | Подпись, значение, контекст; hover без движения; кнопка ведёт к связанному блоку/фильтру. |
| Panel | Тёмная поверхность,16px; информационный контейнер не реагирует как ссылка. |
| Task Row | Иконка, описание, одно действие; компактная/перенесённая адаптация. |
| Vacancy Row | Название, контекст, отклики, статус, действие; Desktopgrid→Mobilegrid. |
| Filter | Default, hover, selected purple; aria-pressed, горизонтальная прокрутка. |
| Status Badge | Green published, amber attention/draft context, neutral draft; обязательно текст. |
| Candidate Row | Default→invited disabled; сохраняет место в списке. |
| Progress | Заполнение компании70%, доступный progressbar. |
| Notification | Временное текстовое подтверждение role=status; без отдельного экрана. |

Hover для интерактивных элементов: фиолетовая кнопка светлеет, вторичная меняет тон и рамку, пункты навигации/фильтры/метрики подсвечиваются. Служебные карточки не прыгают. Focus-visible не заменяется hover. Reduced motion отключает CSS-переходы.

## Проверка решения и дальнейшие гипотезы

Проверка: Desktop1440/1280, Mobile390/320 и промежуточная ширина768; отсутствие горизонтального переполнения; состояние фильтров; раскрытие кандидатов; приглашение; продление публикации; мобильное меню. Иллюстративные данные не подаются как аналитика действующего сервиса.

До продуктового запуска: проверить причины неиспользования главной интервью и аналитикой, согласовать состав метрик и права менеджеров, подключить реальные данные, уточнить правила и оплату продления, события обновления счётчиков и обработку API-ошибок. Критерии будущего теста: время до первого полезного действия, доля входов с обработкой отклика, время первого ответа кандидату и количество необработанных откликов. Улучшения метрик сейчас не заявляются — измерений нет.
